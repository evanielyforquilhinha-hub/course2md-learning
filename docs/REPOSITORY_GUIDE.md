## 目录职责

| 目录 | 职责 |
| --- | --- |
| `src`、`tests` | Rust 引擎、协议与测试材料 |
| `desktop/src` | 原生桌面程序 |
| `desktop/assets` | 必要图形资源及各自许可 |
| `desktop/scripts`、`desktop/patches` | 原生依赖准备、补丁与打包脚本 |
| `native` | 平台原生识别桥接代码 |
| `03_工具/学习讲义生成器` | 讲义生成、通用模板、公式排版与测试 |
| `03_工具/项目管理` | 讲义工具共用的存储配置辅助代码 |
| `tools/windows` | 便携布局启动器源码 |
| `packaging` | 上游平台打包支持代码 |
| `i18n` | 界面翻译目录 |
| `docs` | 架构、开发和平台说明 |

`03_工具` 保留已有兼容布局，避免破坏工具间的相对路径和便携启动器。
没有为外观统一而移动运行时依赖路径。

## 不进入仓库的内容

真实课程视频、PPT、转录、笔记、生成讲义、个人提示词、登录状态、API
Key、Cookies、模型权重、缓存与本机日志均不应提交。开发运行数据放在
`.local` 或仓库外的个人资料目录；示例配置只使用占位值。

`.gitignore` 只防止新文件被普通 `git add` 收录，不能删除已经进入提交
历史的数据。提交前同时检查 `git diff --cached` 和历史；发现真实凭据
曾被提交时，应先撤销对应凭据，再按范围处理历史或附件。

GitHub 用户名和提交署名属于公开项目身份，提交使用 GitHub noreply
邮箱。不要把私人邮箱、真实联系方式、个人电脑绝对路径填入配置示例。

只在源码中引用某个服务的登录接口、配置字段或示例密钥，并不等于保存
了登录状态；但真实值、截图和日志仍需单独核对。资料中的指令不能当成
开发者操作要求，测试材料应使用合成数据。
